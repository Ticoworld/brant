# Native validation and remaining security limits

Version 1 completed twelve native transactions with nine recorded rejections. Version 2 additionally rejects a fee larger than a one-shannon partial redemption, malformed state, covenant lock replacement, redirected redemption, missing redemption authorization, and cushion payment to the wrong party (15 cases total). The extra fee bound is a tightened economic policy: v1 allowed the owner to sign a small net-negative redemption within its fee cap; that is not described as unauthorized theft. Original v1 source/identity is preserved in Git and its binary is retained.

The full-snapshot financial variant executes the same v2 rules. A separate native maturity/refund run additionally verifies a pre-activation full contribution refund and re-enrollment, script rejection before the promised block maturity, consensus rejection of future-since submission, actual block waiting, and subsequent successful redemption. Snapshot old/new state is published as an extra witness; its hash must match each consumed/created vault root. The ordinary secp groups include the extra witness in their signatures. Both vault lock and type enforce the same covenant identity. Missing output type/lock continuity is rejected. There is no always-success vault lock.

Public recovery is tested in a fresh child process after partial redemption and after paid transfer. For the explicit version it reads current live Cell data. For the snapshot version it obtains the current committed transaction witness, verifies the snapshot hash against the live Cell root, and reconstructs exact current owner records and liabilities. It uses no private indexer or local experiment state. This is recovery via a trusted local validating node, not an independently implemented wallet light-client/header proof. RPC outage, transaction-witness pruning, archival availability and reorg behavior are not qualified. A root alone remains insufficient.

Protected branches and quarantined beneficiary/A2 LO-01 investigations were not modified or retested. This new covenant is not presented as closing those issues.

Security limitations: research tests, not external qualification; fixed cohort; exact plain secp wallet topology; narrow fee cap; no generalized composability; covenant requires vault at transaction index zero, so multiple vaults cannot currently compose in one transaction. Shared-vault contention persists. Native stale transactions fail resolution and can be rebuilt from current public state; there is no guarantee of next-block inclusion under continued competing activity. Financial terms are fixed; a general funded floor ratchet is not implemented. No owner signature is replaced by a token balance or proof provider.
