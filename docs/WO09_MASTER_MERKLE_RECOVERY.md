# Independent Merkle reconstruction

Native recovery evidence: merkle-financial-1793667979970. A fresh child process receives only latest transaction hash, expected code hash, market identifier and slot index. It follows committed vault input lineage to valid empty creation, then replays published old/new leaves and paths. Each historical old record is checked against reconstructed state; path/root, successor commitment and aggregate liabilities are verified. The final live Cell must match the reconstructed latest root. No original receipts, cached proofs, keys, local tree or private indexer are supplied.

Alice's remaining entitlement is reconstructed after partial redemption; after paid assignment the child identifies Bob as current owner and supplies his current proof. After another holder redeems, Bob's refreshed proof still matches the latest live root. A final replay confirms complete closure and zero backing. Sample three-owner recovery times were about 67–90 milliseconds, including local RPC retrieval and reconstruction; these are local measurements, not remote archive SLAs or portable performance guarantees.

Controlled withholding of one historical enrollment transaction causes explicit recovery failure. This is a deliberately filtered historical source, not observed chain pruning. It shows the required archive dependency rather than proving data can always be obtained. The snapshot fallback needs the current authenticated snapshot witness, whereas this Merkle representation needs sufficient historical updates or a separately authenticated snapshot to reconstruct missing untouched records. A root by itself is insufficient.

Scale results and memory/recovery measurements will be added only after the scaled run completes. No private indexer availability, arbitrary RPC honesty, header-light-client correctness, reorg resilience or paid archival service is established by the local validating-node experiment.

## Completed native scale and cold closure replay

The successful 16/100/1,000-owner native markets retain fresh recovery after enrollment, after paid assignment and after multiple unrelated redemptions. Child input is only current transaction hash, expected code/market identity and slot; it reconstructs all touched records from public history and verifies the latest live root. No local indexer/tree/receipts are used. Measured enrollment replay times were 72.8/92.6/346.1 ms in this local environment.

After the runner exits and the original node is stopped, recover-closed-scale.cjs restarts the preserved disposable chain, checks its genesis identity, and invokes a fresh recovery process for the closed 1,000-owner market. It retrieves and replays 1,015 committed market transactions, verifies all updates through closure and confirms no outstanding backing. Local time about 2.53 seconds and RSS/peak about 167.3 MB are recorded. This explicitly tests loss of runner state and no stored user proofs, not loss of the validating chain database itself or availability of an independent remote archival provider.

## Current configured result and availability boundary

The configured 184-byte state retains root at bytes 128..159 and adds immutable policy bytes at 160..183. Fresh reconstruction and independent offline verification authenticate those policy bytes throughout history. Native configured runs recover the buyer's entitlement after assignment and after unrelated changes, with no receipt/private-indexer dependency. Latest unclosed reconstruction explicitly queries the referenced vault's live-cell status and matches its root. A stale proof submitted with a current live input rejects; recomputation from public updates succeeds. Actual old-input spending conflicts separately reject in the native resolver.

After restarting the archived configured full-scale node, a new process replays all 1,015 transactions in the closed 1,000-holder market in about 2.45 seconds (172.7 MB peak RSS), confirms all remaining backing zero and lawful closure. Evidence: `merkle-configured-scale-1793671317288/cold_recovery_closed_1000.json`. Controlled missing enrollment history stops reconstruction; this is an explicit availability counterexample, not a successful recovery. The operator can disappear without supplying a signature, but a holder still needs an available validating archive of committed witnesses, current chain access, private owner key and funded wallet. Root possession alone does not suffice. No reorg/pruned-history adversarial network guarantee or archival SLA was tested.

Host-only deterministic tree benchmark separately measures 1,000-leaf construction about 125 ms, generation+verification of all 1,000 paths about 84 ms, peak process RSS about 54.6 MB. Those measurements are labeled synthetic host performance, not native execution or full archival reconstruction. Source and exact output are preserved in `benchmark-merkle-proof.cjs` and `merkle-proof-host-benchmark.json`.
