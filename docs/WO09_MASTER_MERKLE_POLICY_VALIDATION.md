# Configured financial Merkle market: native policy qualification

This supersedes arbitrary-dust admission in the earlier Merkle variants, while retaining their source, binaries and evidence as frozen research fallbacks. It is a bounded native research qualification, not independent security certification.

OBSERVE → WHY: the original framed covenant admitted a 2-shannon contribution with a 1-shannon backed claim. Its refund could not pay the normal fee without reducing prior wallet principal. A one-shannon-fee refund passed script validation but the native transaction pool required at least 1,002 shannons. Final closure correctly rejected outstanding liabilities. Evidence: `labs/wo09-unified/evidence/dust-boundary-1793670840749`. This is an economic/relay-policy failure, not consensus impossibility or theft. Do not label the old design economically safe for arbitrary dust.

REDESIGN → RETEST: isolated configured binary adds immutable minimum contribution, actual funding goal and optional feature flags. It rejects admission below the minimum, activation below the goal, and partial redemption leaving a nonzero balance at or below the 1,000,000-shannon maximum fee. Default flags disable unsolicited donations and sale-funded topups. These guardrails do not guarantee fees remain viable under future relay policies or prevent an owner losing keys/refusing settlement.

Configured source: `labs/wo09-unified/contracts/merkle_market_configured.c`, which explicitly enables the conditional configuration in `merkle_market.c`. Unconfigured build remains SHA256 `925f4c387f34d8c0f2129dfa9cd3587ce6601158b18cdf5d1bbf2684cd2f5a7a`. Configured binary is 17,848 bytes, SHA256 `c569360ba498e715899635410dc0474003e8f61c6afc08a5c3f2a87527711c1f`; code Cell 17,889 CKB, state 184 bytes, minimum vault cushion 322 CKB. No privileged settlement lock or cryptographic verification bypass was introduced.

Native policy run `merkle-configured-scale-1793671167711`: three independently signed contributions initially total 0.375 CKB, below the configured 0.5 CKB goal. Activation rejects. Alice refunds and re-enrolls 0.25 CKB; total reaches 0.5, backing 0.4, creator gross 0.1. Partial redemption, paid assignment, all remaining settlements and closure execute. Below-minimum enrollment, immutable-policy changes, dust residual and default unsolicited donation reject at their intended script rules. Fourteen committed transactions independently replayed.

Full native run `merkle-configured-scale-1793671317288`: 1,156 committed transactions, 2,238 verified leaf updates, complete 16/100/1,000-owner financial markets. Every claim settled and each 322 CKB cushion returned lawfully. Independent offline UTXO/Merkle replay verifies capacities, roots, liabilities, history and committed statuses. Fresh process after restarting the preserved node reconstructs the closed 1,000-holder market from 1,015 public archived transactions in about 2.45 seconds, 172.7 MB peak RSS. It requires historical witnesses; root knowledge alone is insufficient.

Native optional-feature run `merkle-configured-security-1793671585906`: flags 3 explicitly allow funded additions. Two markets, 22 committed transactions, 16 verified leaf updates. Real donor contributes 1,000 shannons and assignment buyer contributes 100,000 shannons on top of seller consideration and miner fee; liabilities and vault gain exactly those amounts. Both markets fully settle and close. This qualifies an optional named-right increase, not a universal rising pro-rata floor.

Adversarial raw cases include wrong paths, arbitrary successor root, duplicate enrollment/update indices, unsupported seeded genesis, wrong ownership, missing/invalid secp authorization, unpaid sale, unbacked increase, stale root/input, malformed/missing/trailing witness, attempted resurrection, early closure and incorrect cushion recipient. A genuine proof from the first market fails against a second actually funded market with identical initial records, establishing the tested market-domain separation. Exact errors and transaction construction are preserved in `cases.json` and compressed raw RPC logs. Resolver, lock, covenant and relay failures are distinct; none is counted as a different intended validation.

NEXT QUESTIONS: can archival availability and wallet rebuilding be provided affordably? Can funded cohort caps and sharding give better concurrency than a global vault? Can a real product justify paying for a protected right instead of retaining its backing outside the market? Optional donations can still produce root churn when explicitly enabled. Neither proof availability under censorship nor unconditional cushion recovery has been established. Quarantined E1/LO-01 work was not resumed.
