# Failed hypotheses and boundaries

1. **“Zero marginal Cell means zero cost.”** Rejected. Existing capacity is capital; fees, VM execution, wallet inputs and liquidity remain. New normal output still needs capacity.
2. **“An immutable root can pay arbitrary exits once.”** Incomplete: immutable leaves repeat. Change root and exits contend; add nullifiers and per-user state returns. Model counterexample only, no vault execution.
3. **“Tiny principal exits by itself.”** Rejected for a new normal61-CKB output with principal below61. Needs existing recipient Cell, supported ACP, sponsor, aggregation or weaker off-chain credit.
4. **“A signature is a resting order.”** Rejected: spent inputs stale a draft; no cell reservation, fill or admission guarantee.
5. **“Fiber/rollup/channel is a generic claim system.”** Not established. Payment routing, programmable conditionals, durable liabilities and independent close are distinct properties.
6. **“Transferable E1 beneficiaries are ready.”** Unresolved and quarantined. E2 does not validate or rename that correction.
7. **“A 32-byte root alone proves cheap independent exit.”** Rejected as an incomplete design claim. Liquid Cells' tested script requires an authenticated proof path, a nullified successor root, exact accounting and a key-derived payout. The shared anchor still serializes exits, archived DA is needed to reconstruct proofs, and sub-floor balances do not have unilateral standard-Cell payout. One private-devnet exit now passes, but cold DA retrieval, concurrency and below-floor recovery have not been exercised.
8. **“CKB-testtool success proves the binary executes on the actual node.”** Falsified. The first pinned binary passed CKB-testtool but CKB 0.210.0 rejected it with an A-extension `lr.d` instruction. Building from the crate directory loads its local `-a` setting; removing `+forced-atomics` alone then exposed `bytes 1.11.1` atomic refcounts. An isolated single-hart dependency patch without `Send`/`Sync` produced a binary that passed the 24 VM tests and the private-chain lifecycle. This is an experimental compatibility variant, not an upstream fix.
9. **“The pinned genesis deposit is below CKB's occupied-capacity floor.”** Falsified by execution. The fixture deposits 10,000,000,000 shannons (100 CKB) with a 9,300,000,000-shannon occupied floor for its 32-byte data and secp lock; the private devnet accepted and committed it. Earlier rejection harnesses were assertion mistakes because `Engine.reject` correctly treated the accepted transaction as unexpected; both attempts remain preserved under `labs/wo09-e2-capacity/evidence/liquid-cells-genesis-fixture-occupied-capacity-1793614920150` and `...1793614925492`.

The native evidence now includes the whole-body xUDT/CKB swap and one bounded Liquid Cells lifecycle, as detailed in `WO09_E2_PRIVATE_DEVNET_LIFECYCLE.md`. Fee competitiveness, chain-only archive recovery, competing exits, sub-floor payouts, and production security remain unproved. Earlier invalid-instruction, malformed-witness-signature, and malformed-anchor-draft failures remain in their raw evidence directories and are not counted as protocol rejections.
