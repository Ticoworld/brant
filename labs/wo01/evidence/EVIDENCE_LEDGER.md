## Evidence gaps that determine the verdict

* Mainnet transaction latency and realistic secure settlement throughput: unmeasured.
* CoBuild contract cycles/wallet compatibility: not executed.
* Actual two-chain escrow and timeout recovery: not executed.
* Correct native CKB/native-USDC portfolio-channel unilateral settlement: not established.
* Current iCKB reserve liquidity and maker availability: not measured.
* Kaze routing mechanism, custody during swaps and executable prices: unknown.
* Detailed Remit/Sluice implementation audits were not needed or performed. The saved operating-rules record was read for the strategic repetition check; their product categories were not assumed identical to this trading proposal.
* Customer willingness to pay and maker profitability: unvalidated.

## Retrieval failures and scope boundaries

Some GitHub browser/search fetches were disabled, so raw official repository URLs/API trees were fetched directly and preserved instead. The old dev-log search snippets lagged the latest release; the release API and actual binary took precedence. UTXOSwap's overview returned HTTP 503 during this run, so its current operating state was not used as an independently established premise. No conclusions rely on claims that every old CKB exchange is dead.

The source snapshots contain upstream material for audit/reproduction, not endorsements. `SHA256SUMS.txt` detects later file changes. The release archive checksum is recorded in `experiments/reproduce.md`; the archive is omitted from the deliverable ZIP because the pinned official binary can be fetched again.
