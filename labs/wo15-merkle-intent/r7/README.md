# WO15-R7 CCC intent experiment

VERIFIED: the installed @ckb-ccc/core 1.23.0 SignerCkbPrivateKey.signMessageRaw produced recoverable signatures accepted by this experimental covenant in private CKB 0.210.0 transactions. This is not a physical wallet test or a production deployment. R6 remains unchanged.

The canonical message is `saleMessage` in intent.cjs. All integers are unsigned canonical decimal shannons or indices, hashes are lowercase 0x-prefixed 32-byte hex, and the separator is LF. The string discloses scope and no expiry. The covenant independently reconstructs it from authenticated chain state and witness values, prefixes `Nervos Message:` and hashes using CKB Blake2b, then recovers the compressed key from CCC's compact r||s||recovery-id signature. The inherited contract hashes the canonical 73-byte Molecule standard lock script derived from that key and checks the complete lock hash against the leaf. The genesis header is bound at vault creation. A shared-genesis fork is not distinguished. The recipient is the seller lock hash; the price is a minimum and the buyer is unspecified. Revision advances on every change, including revocation.

`node labs/wo15-merkle-intent/r7/ccc-test.cjs` tests installed CCC's disposable signer, recovery, modified price and string-vs-bytes semantics. `bash labs/wo15-merkle-intent/r7/build.sh` uses R6's pinned upstream dependency and compiler setup. `node labs/wo15-merkle-intent/r7/run.cjs` starts a disposable private chain; the preserved R5 harness is adapted in memory to R7's signature and stride. Never point it at a public network. `node labs/wo15-merkle-intent/r7/verify.cjs <evidence-directory>` independently replays recorded transaction data and verifies CCC signatures, seller payouts, proofs, revisions and backing preservation. It relies on recorded private-node history, not independently verified consensus.

The first committed sale after an unrelated root change is `0x692235928318ff432984d3635466d425077e5da411bd1eca1e25c522d3dbc253`, in evidence/r7-1793925715258. The harness tested malformed signatures, wrong maker, wrong network, underpayment, redirected payout, duplicate position, replay after ownership returned and revocation with intended covenant rejection codes. It also committed a two-maker batch. The replay found three valid sales. Current run directories also include the modified-signed-price negative case.
