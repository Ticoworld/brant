# Trade V2 token-order integration: reuse boundary

Status: experimental and incomplete until native token-order and browser gates pass. WO17C remains the runnable outpoint-bound fallback. Its sale is buyer-specific and is invalidated by any transition of its custody outpoint. No WO16 issuer or xUDT binary correspondence limitation is resolved here.

R7 `labs/wo15-merkle-intent/r7/merkle_intent.c` implements indexed membership, current-root transition, per-leaf revision, revocation (op 9) and open-buyer signed claim transfer (op 8). `candidate.c` implements CCC `Nervos Message:` hashing and recoverable secp256k1; `r6/secp256k1_helper.h` supplies pinned secp integration. R7's existing leaf contains financial principal/backing/revision and cannot be treated as an xUDT entitlement. A token-specific domain and message are required; do not reuse that claim message as authorization for tokens.

A token covenant must authenticate its unique singleton lineage, exact xUDT type and complete current state. An indexed Merkle proof alone proves neither unique ownership nor the sum of balances. A bounded implementation can provide all leaf preimages and recompute the tree, check nonzero owners are unique, reserve owner/tombstone and increasing revision permanently, and enforce the exact sum equals xUDT backing. Every purchase, sale, revocation and withdrawal must enforce the corresponding token and balance deltas; xUDT conservation alone permits burning. Buyer creation needs an authenticated empty slot and uniqueness check. Collisions or slot exhaustion must fail closed. Sequential Merkle updates must use proofs relative to each intermediate root. A seller message binds chain, market, xUDT, custody identity, seller/index/revision, quantity, minimum payout, payout lock and order ID, not buyer, shared root or outpoint. The buyer transaction binds its own funding input and receipt, and seller inputs must not subsidize the payment. Automatic upper time expiry is not claimed.

The existing `apps/trade-testnet` R7 interface and server are built around financial claims. Wallet connection, transaction status and loopback/genesis safeguards can be reused, but discovery, replay, balance model, transaction builders and signing domain must be adapted to actual xUDT custody before a browser flow can claim chain-backed token ownership. SQLite offers are distribution, not ownership. A private fixture-backed browser is not physical-wallet acceptance.
